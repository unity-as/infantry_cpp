# module-removal —— 删除模块/应用子系统

> 删除是最不可逆的操作之一。本 skill 每一步都必须有输出物并经确认。
> 行为流程遵循 change-discipline。

## 1. 删除前审查（第一步，不做不许删）

- rg 搜索谁引用了它：include、函数调用、配置表、任务挂载、bus 队列、发布订阅话题
- 列出所有引用点——这是删除清单的依据

## 2. 依赖分析（三种情况）

- 独立模块：没人引用 → 可直接删
- 被依赖模块：其他模块用它 → 禁止直接删，先改依赖方或报告用户
- 连带模块：它依赖的东西删不删，一起评估

## 3. 可回滚前置

- 确认 git 基线存在、当前状态干净；没有 git 先建仓或手动备份
- 删除前记录被删文件的内容（git 提交或备份），确保可恢复

## 4. 列删除清单（等用户确认）

- 文件路径、将删内容、影响范围（含引用点）、连带影响
- 用户确认后才允许动手

## 5. 执行删除

- 禁止递归删除（禁止 rm -rf 类宽泛命令）
- 优先移动/改名到临时目录（或回收站）而不是直接删，确认无误后再清
- 明确验证目标路径在项目内

## 6. 删除后收尾

- 更新：CMake 手动文件列表（自动扫描则免）、README 模块地图、模块清单、ONBOARDING 索引
- 应用子系统还要清：robot.c 的 Init/Task 调用、robot_task.h 任务挂载、
  robot_bus 队列、message_center 话题
- 相关 .ioc 外设配置：引脚不再使用则同步清理

## 7. 删除后验证与报告

- 编译通过；相关功能没坏（验证 A 没坏）
- 报告：删了什么、是否可恢复
- kit 里的模块删除更慎重：影响所有引用项目，能标记 deprecated 就不删
