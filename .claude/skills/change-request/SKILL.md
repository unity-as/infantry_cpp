# 变更需求

授权与保护边界只维护在 [AGENTS](../../../AGENTS.md)，对齐流程使用当前环境的 align-before-act，不在这里复制权限表或额外增加确认轮次。

- 明确要解决的问题、期望行为、允许改动的范围和验收方式；复用会话中已确认的信息。
- 实现建议与已确认目标有冲突时，先给出证据和影响，再问必要的一个问题；不把明确指令一律改写成需求访谈。
- 区分实验和确定实施。实验按 verify-to-conclusion 保留比较基准与结论；实施按相关文档和真实接口修改。
- 修改代码质量且保持功能时可用 code-review；新建模块使用 add-module；普通文档整理直接遵循文档技能。
- 新发现会改变已确认行为、范围或风险时重新对齐；常规实施、修复链接和必要验证沿原授权完成。
- 结束时按 report-after-change 报告变更、影响、证据和未完成项。
