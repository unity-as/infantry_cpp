# 改动 / 拓展已有内容，怎么提

**只管一件事**：项目里已有的、本来在跑的某部分要改或要拓展时，把这个需求提对。

**为什么单拎出来**：改"已有的、本来能跑的东西"，比从零写更危险——等于把已经对的东西推回赌桌。所以提法要更讲究。

**面向谁**：把 AI 当贩卖机、张口就甩解法（"改 step1""扩规模""换个库"）的新手。他不会主动喊我、不会在我偷偷开改时拦住、需求会答得乱。所以我**主动拦、牵着走、容忍乱答**。

---

## 什么时候启动

闻到"要动已有的东西"就先别照做：改 X / 加 Y / 换 Z / 扩规模 / 调参 / "试试看会不会更好"。
先复述我听到的，说"动手前先跟你确认两件小事"，再进下面流程。手动唤起：`/change-request`。

---

## 红线：动手前先查权限

改动目标若命中 `.claude/CLAUDE.md` 的红线，必须**先征求同意再动**：

| 文件 / 目录 | 权限 | 处理 |
|------|------|------|
| `Core/Src/main.c` | 未经允许禁止更改 | 先问是否同意 |
| `.claude/conventions/` | 未经允许禁止更改 | 先问是否同意 |
| `.claude/skills/` | 未经允许禁止更改 | 先问是否同意 |
| `CMakeLists.txt` | 未经允许禁止更改 | 先问是否同意 |
| `Drivers/` | 绝对禁止更改 | 用户提出时警告 |
| `Core/` | 绝对禁止更改 | 用户提出时警告 |

若文件未明确维护者，改动前同样要征求同意。

### 边界：这是"功能"线，不是"质量"线

- 只改**代码质量**（可读性 / 性能 / 健壮性）但**不改功能** → 走 `code-review`（含优化）。
- 改功能 / 加功能 / 换实现 / 扩规模 / 调参 / 换库 → 本流程。

## 一个"提得好"的改动请求，要说清这几样

> 全程**一问一答、开放式**：每轮只问一个，等答完再问下一个；不 A/B/C 轰炸，不一次甩多问。容忍乱答，一层层兜。

1. **别接解法**：他给的"改 X"先当**线索**，不当**指令**。复述回去确认没听岔。
2. **事**：你当时在干嘛、发生了什么？——要具体真事。
3. **痛**：哪儿疼 / 卡在哪 / 不放心什么 / 要加什么？
4. **重建真需求**：从事+痛说出"你其实想得到的是 ____"，请他确认。**常和他最初甩的解法不一样。**
5. **定性质**：这是"**试一下（实验）**"还是"**定了要改**"？
   - 实验 → 必须**小步、保留原版、可回退、能干净对比**。越是"随便试试"，越要改得小、留后路。
6. **自由度**：**照搬**还是**改良**？**严格照做**还是**你看着办给建议**？（不说清，我会替你定，方向你没看过 → "乱改"。）
7. **红线**：什么**绝对不许动**？目标**优先级**是什么？——"X 是这次最看重的，谁都不许为了跑通把 X 偷偷砍了。"
8. **先方案后动手**：我先说"打算怎么改、动哪些、代价多大"，你点头，才落手。
9. **检验**：改完代码后，我要记得检查可能的受影响的文件

## 对称的另一半：我自己要动已有的东西时，同样守规矩

当**我**准备改已有内容（尤其动上游、要重训、改既定做法、删/重写既有成果）：
- 把"我发现的问题"当**假设**，不当事实——一个现象往往多个嫌疑，别一口咬定。
- **摊牌再动**：发现了什么 / 依据 / 打算怎么改 / 牵动哪些 / 代价多大 →**停，等点头**。
- 撞到工具天花板，不准为跑通**偷偷砍目标**，把"换工具还是接受小规模"摆给你选。
- "我猜对了" ≠ "我可以不打招呼动手"。

---

## 真实反面教材

- **step1 单词**：张口"改 step1"（解法）。真需求其实是"想试试换个写法会不会更准"（实验）。结果用"分析优势 → 就此整段改"的高自由度话术，把"照搬试一下"说成"放手改良"，一改就卡，连"好不好"都没测出来。
- **直推式 / 扩规模**：数据集内 100%、数据集外 60%。AI 一口咬定"不分数据集的训练法错了"，没确认就改最上游的训练划分。本该当假设摊牌、先确诊（真实部署是直推还是归纳？）再动。
- **不探讨内容 一直问用户是否执行**：用户没说清楚需求，不提出有效的问题，一直模糊地说解决方案并问是否动手。我应该把所有细节确认好，提出问题和内容，并保证用户理解到位了，再问用户是否点头确认。

---

## 一句话内核

**先目的后方法；解法只当线索，事和痛才是入口；试一下就小步留原版；动手前，先方案、再点头。**
