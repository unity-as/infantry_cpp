# 代码审查与质量改进

遵循 [协作入口](../../../AGENTS.md)。仅审查的请求不授权修复；明确要求修改时，按已确认范围实施，不重复询问已回答的信息。

- 从用户指定范围和重点开始；只有对象或约束无法从上下文确定时才询问。
- 对照负责文档、接口、调用者和现有验证，区分源码事实、推断和未覆盖的运行行为；证据不足时执行 research-with-evidence。
- 以“位置、现象、触发条件、影响、证据”记录可行动问题，按重要性完整汇报。需要用户判断的设计取舍单独提出，不要求用户逐项确认每个已证实事实后才继续审查。
- 质量改进保留行为和接口；若改动需要改变功能或保护策略，按 change-request 对齐范围。
- 验证覆盖实际改变的行为；不以构建通过代替运行正确，也不为风格改动追加无关测试。

编码规则见 [C++ 规范](../../docs/cpp/cpp_conventions.md)，接口入口见 [API 导航](../../conventions/api.md)，依赖边界见 [工程结构](../../conventions/file.md)。
