# 消息总线解耦意向

未实施，状态见 [当前待办](../records/todo/current.md#功能待办)。现有共享指令与直接调用链见 [系统架构](../docs/impl/architecture.md#任务与数据流)。

目标是让 cmd 负责输入转换，各子系统消费自己的命令并拥有行为逻辑；裁判数据和子系统状态按需要分发，减少 cmd 的跨模块协调。

旧 C 方案中的动态 topic、malloc 链表和 Register 接口与现行 [C++ 约束](../docs/cpp/cpp_conventions.md#基本约束)不兼容，不作为执行清单。原方案可在 Git 历史中查看。

若继续推进，需先决定：是否确有消息总线需求、topic 和容量的静态管理方式、类型及生命周期、ISR 与任务之间的一致性、数据新鲜度/失效语义，以及迁移后是否保持控制与停机顺序。尚未选择具体实现，不能假定裸指针共享结构就是一致快照。
