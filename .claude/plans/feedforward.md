## 自瞄速度前馈

优先讨论由视觉提供目标角速度或经过坐标转换的前馈量；本仓库不能证明视觉侧已有可直接复用的速度输出。需要先确定来源、单位、符号、时间戳、有效位及超时策略，再决定扩展报文和控制入口。

旧“STM32 再做目标速度估计”的提法不作为既定实现。应先核对两端职责，避免重复估计；当前接收帧没有速度字段。

## 其他设计意向

底盘/云台速度环的摩擦电流前馈曾讨论 `I_ff = sign(omega_target) × (a×abs(omega_target)+b)`：通过恒速测量拟合参数，在功率预测前与 PI 输出合成。适用性、符号过零、采样方法和保护还未验证，不能直接采用旧笔记“无需平滑”的结论。

RLS 在线功率辨识及受约束电流分配见下方资料整理；[通用 RLS 库](../../project/modules/alg/rls/README.md)已从 `leg_main` 移植，应用侧模型与分配器需分别评估。源码错误只维护在 [RLS 移植核对](#rls-功率模型移植核对2026-11-10)。

### 区分输入功率与底盘负载功率

定义 `P_ref` 为裁判 Chassis 供电边界进入功率控制链的电功率，`P_load` 为超电模块向底盘输出的电功率。对没有其他能量支路的边界，能量守恒给出：

```text
P_ref = P_load + dE_cap/dt + P_loss
```

`dE_cap/dt > 0` 表示充电；放电时可出现 `P_load > P_ref`。因此单独测到 `P_load`，不能确定 `P_ref`，也不能由此确定可持续爆发预算；还需储能变化、转换损耗和模块控制能力。实际接线有其他负载时，必须先修正能量边界。

裁判缓冲能量、物理电容剩余能量和比赛机制中的底盘能量是不同状态，不可互相替代。尤其不能因超电输出功率在线，就直接提高裁判输入预算或长期放开底盘。

### 职责与电流分配方向

| 位置 | 负责内容 |
|---|---|
| `chassis.cpp` 应用层 | 根据裁判、模块能力、在线状态和操作模式决定预算与回退；决定是否允许采用新模型参数。 |
| 超电驱动/协议层 | 解释测量边界、单位、状态、新样本及超时；发送模块实际支持的指令。不替应用制定比赛策略。 |
| 底盘功率模型与分配逻辑 | 将速度环及前馈合成后的电流需求代入模型，按给定预算限制四轮输出；将实际限制量反馈到抗积分饱和环节。具体代码归属在实施时确定。 |
| 通用 RLS | 只完成参数估计；不接裁判、不决定预算、不判定物理可信度、不发送电流。 |

模型从 [核对记录中的损耗模型](#来源与职责)出发，把其 `P_measured` 明确为覆盖相同四轮及已计入附属负载的 `P_load`。若测量边界含会变化的其他负载，不能一概归入常数项。转速一次项与转速平方项是不同候选模型，先用独立数据比较，不同时堆入更多参数。

力矩与转速须对应同一轴侧，统一为 N·m 和 rad/s；先核对电流原始码到 A、转矩常数、减速比及 deg/s 换算，不能将转子力矩与轮轴转速直接相乘。预测使用合成后的待执行指令，辨识使用对齐后的实际反馈；两者不能混用。

新的分配器先建立能独立验证的简单基线：对四轮合成电流统一取 `0 <= alpha <= 1`，在固定当前转速、参数物理有效的假设下，损耗模型对应 `P(alpha) = A·alpha² + B·alpha + C`。优先由二次/一次方程及区间直接确定可行缩放量；不是继续使用仅对机械功率成立的 `limit / prediction`。不预设引入迭代优化器，也不将此基线称为最优分配。

后续若实测证明统一缩放影响转向、平移或动态响应，再明确性能目标后评估按轮分配；不能只凭速度误差大就判定应获得更多功率。需处理的边界包括零误差、静止大电流铜损、制动回馈、一次退化、负判别式、预算无可行解、符号及单电机电流限制。不能用错误根强制反转，不能在无可行解时假称满足功率上限。

RLS 样本使用反馈电流/力矩和对应时刻转速，不使用未执行的 PID 原始需求代替实际状态。只消费新有效功率样本；处理传感器滤波延迟、窗口平均、尺度、低激励和参数边界。在线更新先作为观测运行，未经独立数据与采用条件检查，不直接替换控制模型；制动样本在符号和回馈能力未确认前单独记录。

### 后续实施顺序与验收依据

1. 先核对本车超电协议和电路边界：功率单位/正负号、采样及滤波周期、序号/时间戳、可用状态、能量字段、输入/输出指令、硬件保护、超时行为与物理旁路。没有这些证据，不指定本车 CAN 报文或宣称具备输入闭环。
2. 先整理上限决策的工况与失败语义，再修改 `chassis.cpp`；范围保持为功率上限决策。缺数据、启动、裁判失联、超电失联、能量低和恢复均需有明确输出。
3. 获取独立实测数据并离线标定，分开拟合与验证数据；覆盖静止带载、启动、匀速、转弯、制动及不同母线电压。比较总功率偏差、峰值低估、窗口能量偏差和重复性，数值门槛由本车需求确定。
4. 用固定可信参数验证解析分配基线、边界与积分回灌，再让 RLS 旁路记录参数及残差。分别评价功率误差与运动跟踪误差，不能仅以参数看似收敛作为通过。
5. 确认参数采用、异常回退和切换连续性后，再评估闭环启用在线辨识及储能策略；测量 Cortex-M4 最坏耗时、栈占用、真实采样/控制节奏和 CAN 延迟。主机测试、构建、通信及实车功率效果分别记录。

### 功率分配与数值保护的额外问题

- 参考 `getControlledOutput()` 在超功率分支直接计算 `abs(setAv-curAv)/sumError`（`PowerController.cpp:199`）。当四轮速度误差全零但模型功率仍超限时分母为零；即使 `errorConfidence` 为零，随后的 `0 × NaN` 也不能恢复有效权重。复用分配器时须明确零误差回退与输出有限值检查。
- 参考 `RLS::update()` 没有输入有限值、分母有效性、协方差有效性检查，也没有失败回滚；这是可确认的保护缺口，具体发散条件尚未实验。外部对 `k1/k2` 使用 `fmax` 并不能代替内部估计状态的约束和异常处理。

### 当前采样缺口与实施边界

实车采样事实统一见 [底盘功率采样条件](../conventions/hardware.md#底盘功率采样条件)。当前缺少独立的 `P_measured`，母线电压和模型自身估算值不能替代训练观测；因此不具备按上述模型开展在线损耗辨识的完整输入条件。当前底盘的 `Chassis_GetPower()` 也是电机反馈上的模型估算，不能用它验证或训练同源功率模型。

这描述的是当前已接入条件，不表示没有待接入硬件。用户后续补充的超电输出侧观测能力，以及同步、回馈、单位换算和失效处理的实施方向，统一见上方 [资料与实施思路](#底盘功率资料与实施思路)。底盘负载模型辨识不要求必须实测裁判输入侧功率，但要求独立实测值与模型覆盖同一供电边界；裁判输入限功率另行核对。
