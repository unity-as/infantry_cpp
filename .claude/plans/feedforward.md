# 前馈设计意向

本文件是未实施设计，状态由 [当前待办](../records/todo/current.md#功能待办)维护。当前云台接口与执行链见 [云台](../../project/application/gimbal/README.md)，实际自瞄输入见 [通信契约](../docs/impl/aim.md)。

## 鼠标速度前馈

设计思路是保留位置目标累加，将鼠标角度增量除以实际到达间隔作为速度前馈。需要记录真实帧时间、明确滤波和保持方式，处理鼠标静止、断流、模式切换时的清零；不能把固定名义帧率当实测间隔。

core 已有 `Gimbal::setVelocityFF`，应用层没有相应调用；旧 C 的 `Gimbal_SetVelocityFF(gc, ...)` 不再作为可复制接口示例。是否暴露应用包装及如何和位置限位协调，实施前再确定。

## 自瞄速度前馈

优先讨论由视觉提供目标角速度或经过坐标转换的前馈量；本仓库不能证明视觉侧已有可直接复用的速度输出。需要先确定来源、单位、符号、时间戳、有效位及超时策略，再决定扩展报文和控制入口。

旧“STM32 再做目标速度估计”的提法不作为既定实现。应先核对两端职责，避免重复估计；当前接收帧没有速度字段。

## 其他设计意向

底盘/云台速度环的摩擦电流前馈曾讨论 `I_ff = sign(omega_target) × (a×abs(omega_target)+b)`：通过恒速测量拟合参数，在功率预测前与 PI 输出合成。适用性、符号过零、采样方法和保护还未验证，不能直接采用旧笔记“无需平滑”的结论。

RLS 在线辨识及受约束电流分配也只是备选方向；先明确现有等比限流的不足与验证指标，再决定是否值得增加复杂度。源码对照与采样缺口见下方核对记录，当前没有移植或验收结论。

- `leg_main`：分支 `codex/rls`，提交 `e4b09f5e8102dadf89f7a079b4828839cd530874` 的 `project/modules/alg/rls/{rls.h,rls.cpp,README.md}`。它未出现在本次查看的 `leg_main` 当前工作区，使用 Git 对象读取，没有切换对方分支。相邻仓库存在时可用 `git -C ../leg_main show e4b09f5e8102dadf89f7a079b4828839cd530874:project/modules/alg/rls/README.md` 追溯说明。

参考功率模型为 `P = Σ(τ·ω) + k1·Σ|ω| + k2·Στ² + k3`；`RLS<2>` 只估计 `k1/k2`，`k3` 由外部提供。训练输入为 `phi = [Σ|ω|, Στ²]`、`y = P_measured - Σ(τ·ω) - k3`。在线估计与四轮电流分配是两项独立职责，搬入通用 RLS 不等于已经实现功率控制。

### 参考实现的确定错误

以下是源码可直接确认的接口、初始化及校验错误；未通过本轮编译或实验复现，不将其影响写成已发生的实车故障。

| 位置 | 错误与影响 | 后续移植要求 |
|---|---|---|
| `RLS.hpp:98`，`validate()` | `lambda >= 0 || lambda <= 1` 对有限数恒成立；零、负数或大于 1 的值均可通过，而更新式会除以 lambda。 | 检查有限数及 `0 < lambda <= 1`，失败须显式返回，不能只依赖运行期断言。 |
| `RLS.hpp:35`，带初值的构造函数 | 委托构造已将 `paramsVector` 清零，函数体只写 `defaultParamsVector`，指定初值没有成为当前估计。 | 初始化时明确提交参数初值；参考 Manager 随后调用 `setParamVector()` 避开此路径，不代表该构造接口正确。 |
| `RLS.hpp:41–45`，`reset()` | 总将估计参数清零，`setParamVector()` 保存的默认向量未被使用，不能恢复已设置的默认参数。 | 明确重置到零还是调用者提供的先验；不保留无效的默认参数状态。 |
| `RLS.hpp:81`，`getParamsVector() const` | const 成员函数返回非 const 参数引用；调用并实例化该模板成员时，不能将 const 成员绑定为可写引用。 | 提供只读参数访问，修改走明确接口。 |
| `RLS.hpp:88,114`，`getOutput()` / `output` | 构造、重置和更新均未维护 `output`；自动存储对象可能读到未初始化值，静态对象也只有零初值，不能代表模型预测。 | 提供使用回归量计算的预测接口，或删除无效 getter。 |
| `PowerController.cpp:44,64`，Manager 构造 | 接收 `lambda_`，实际构造却固定传入 `0.99999f`，调用者设置的遗忘因子不生效。 | 将应用配置传递到估计器，并核对实际样本更新节奏。 |
| `PowerController.cpp:347`，无超级电容分支 | `manager.estimatedCapEnergy = 0.0f` 缺少分号；该预处理分支启用时存在语法错误。 | 若复用外围代码，需单独编译核对相应配置分支。 |

### 功率分配与数值保护的额外问题

- 参考 `getControlledOutput()` 在超功率分支直接计算 `abs(setAv-curAv)/sumError`（`PowerController.cpp:199`）。当四轮速度误差全零但模型功率仍超限时分母为零；即使 `errorConfidence` 为零，随后的 `0 × NaN` 也不能恢复有效权重。复用分配器时须明确零误差回退与输出有限值检查。
- 参考 `RLS::update()` 没有输入有限值、分母有效性、协方差有效性检查，也没有失败回滚；这是可确认的保护缺口，具体发散条件尚未实验。外部对 `k1/k2` 使用 `fmax` 并不能代替内部估计状态的约束和异常处理。

### 与 leg_main 的 RLS 对照

| 项目 | RM2024 参考 | leg_main 的 `codex/rls` 版本 |
|---|---|---|
| 依赖与维数 | 模板维数；依赖 Matrix、FreeRTOS 和任务 tick。 | 编译期维数，对象持有参数、协方差及暂存区；无堆、无 HAL/RTOS/矩阵库依赖。 |
| 配置与重置 | 存在上述遗忘因子、初值、默认参数恢复问题。 | `init()` 校验有限值、遗忘因子范围和正对角先验；`reset()` 接收显式参数及协方差，空参数表示零初值，不承诺恢复历史默认值。 |
| 更新与失败 | 单条标量观测；原状态直接更新，没有失败返回。 | 同一拍可输入多条标量方程，仅遗忘一次；使用候选状态，整组成功后提交，失败返回 false 并保留原参数及协方差。 |
| 输出 | 参数 getter 有 const 错误，预测 getter 未维护。 | 只读参数访问；`predict(phi)` 实际计算预测，无效输入返回 NaN。 |
| 数值边界 | 缺少异常输入及更新结果检查。 | float 状态、double 中间量，检查非有限值和溢出；该版本 README 仍明确保留低激励、相关回归量下 float 协方差退化及静默停滞风险，返回成功不表示已收敛。 |
| 物理有效性 | 参考功率 Manager 负责样本与外部系数处理。 | 通用库不保证可辨识性或物理参数约束；同步、尺度归一化、激励与样本门控、参数采用条件由应用负责。 |

后续如接受移植，优先评估 `leg_main` 的通用估计器接口；参考功率模型和解析电流分配单独适配。此处是源码评估建议，尚未授权或实施移植。`leg_main` README 记载的既有测试与 Cortex-M7 构建结果不等同于本项目 Cortex-M4 的验证，更新耗时和控制周期预算仍需实测。

### 当前采样缺口与实施边界

实车采样事实统一见 [底盘功率采样条件](../conventions/hardware.md#底盘功率采样条件)。当前缺少独立的 `P_measured`，母线电压和模型自身估算值不能替代训练观测；因此不具备按上述模型开展在线损耗辨识的完整输入条件。当前底盘的 `Chassis_GetPower()` 也是电机反馈上的模型估算，不能用它验证或训练同源功率模型。

后续须先明确底盘输入功率的测量边界、功率与电机反馈的同步/新样本标识、失联/无效值处理、制动回馈语义，以及转矩常数、减速比和 deg/s→rad/s 的单位换算；再确定先验、物理参数边界和对照指标。只有新有效观测到达时才采用对应样本，不能按任务频率反复把旧功率反馈当成新观测。当前未接入 RLS 或改动正式功率控制。
