## 何时更新

- 接口或行为变化：更新负责模块说明；跨模块关系变化时再更新架构或契约。
- 调参：改参数源；只有单位、含义、调参方法或适用边界变化时才改说明。
- 新增、删除、移动文件：修复受影响的链接；目录职责或查阅入口发生变化时才更新结构和索引。
- 完成待办：从活动清单移除；需要保留的验证证据放到验证记录，代码改动过程留在 Git。
- 方案落地：将实际行为写入负责文档，删除已被替代的方案；有长期价值的历史理由明确标注版本后保留。
- 文档整理：核对相对链接、章节锚点、编码及源码依据。只改文档时不因此重复固件和实车测试。

## 篇幅与历史边界

模块默认一份 README，按需设置概述、数据流、接口、执行流程和设计理由章节，不强制拆五个文件或建立“未写”占位文档。只有内容足够独立时才拆分，并从负责文档链接。

当前说明不得夹带旧接口示例或未经实现的设计。历史结果不得改写成当前验证通过；归档时注明原始来源、代码版本和未测范围，不为一次整理另建重复交接文档。

Markdown 使用 UTF-8；保留原始资料中的图片和来源。外部参考资料不参与日常项目事实同步。
