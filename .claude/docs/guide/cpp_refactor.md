# C++ 重构计划（给人看）

> 本文档是 `cpp_refactor.md`（AI 版）的**人读版**，讲清「迁移怎么执行、按什么顺序」。可看可不看，故为**临时文档**。
> 具体 C++ 编码规则见同目录 `cpp_conventions.md`。

## 目标与铁律

把步兵机器人电控代码从 C 迁到 C++，利用面向对象提升可读性、可维护性，同时：

1. **不改逻辑**——这是移植不是重写，数据流顺序、计算精度、回调时机、保护行为都保持原样。
2. **禁堆**——不用 `malloc/free/new/delete`，对象走全局/静态或栈。
3. **数据流对齐**——每个模块的数据流动顺序和 C 原版一致。

## 每个模块怎么迁（通用方案）

以「结构体实例 + 全局指针 + 传参函数」的 C 模式为例，统一转成三步：

| C 原版 | C++ 版 |
|--------|--------|
| `DJIMotor_Instance *m = DJIMotor_Register(&config)` | `DJIMotor motor;`（全局声明，构造只零初始化） |
| —（Register 里初始化外设） | `motor.init(config)`（外设初始化延迟到这里） |
| `DJIMotor_Set_Velocity(m, 1000.0f)` | `motor.setVelocity(1000.0f)`（删实例指针，用 this） |

配套决策：

- **成员可见性**：跨模块要读的状态数据（速度、电流、角度、valid）保持 `public` 直接读，贴合原数据流；内部机制（hal 句柄、缓冲、回调指针）`private`。
- **内部辅助函数**：C 的 `.c` 内 `static` 函数全变 private 成员函数。
- **回调**：函数指针私有 + `setCallback(...)`，保持 `void* device` 显式传实例（不用 `std::function`）。
- **定义头/第三方**：SEGGER_RTT、寄存器/协议定义头保持原样，`extern "C"` 包裹即可。

## 迁移顺序（自底向上）

按依赖从下往上，每迁完一层编译一次：

| 阶段 | 内容 |
|------|------|
| ① utils | 矩阵库、位标志宏（✅ 已完成） |
| ② 算法层 | 卡尔曼滤波、Mahony、AHRS、PID（PID ✅） |
| ③ 板级 bsp | CAN / 串口 / SPI / 定时器 / GPIO / PWM / DWT / I2C / ADC / 日志 |
| ④ 基础模块 | CRC、看门狗、串口管理、DWT 守护、RGB 灯 |
| ⑤ 传感/通信 | IST8310、BMI088、裁判系统、功率、遥控、miniPC 通信 |
| ⑥ 电机 | DJI 电机、舵机 |
| ⑦ 应用层 | 底盘、云台、射击、指令、电机测试（robot ✅） |

## 完成后怎么报告

每个模块迁完、编译通过后，AI 会按统一模板报告：核心改动映射、内存与实时性审计、保留逻辑验证点、编译状态、遗留问题。
