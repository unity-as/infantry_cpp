# 底盘功率控制架构重构

> 最后更新：2026-08-17
> 覆盖范围：底盘控制架构重构（运动学 / 电机反馈链路 / 功率控制 三模块拆分）+ 二值动态限功率
> 关联：[design-rationale.md](design-rationale.md)（运动学）、[data-flow.md](data-flow.md) / [pipeline.md](pipeline.md)（现码路径）

## 一、动机

速度环现在锁死在 `dji_motor` 内部（`DJIMotor_Set_Velocity` → 内部跑 `pid_velocity` → 电流直接发出），chassis 层碰不到「速度环输出的电流」，没法在中间插功率限流。这是底盘**特定四个轮子**的需求，不是通用电机的事。

解法：放弃速度模式，速度环外置、自己产出电流，再用 `DJIMotor_Set_Current` 发出（dji_motor 已有此 API，**不用改电机模块**）。

## 二、职责划分

顶层 `chassis.c/.h`：**只做指令对接**（cmd ↔ 底盘），不干活。

下层三个模块：

1. **运动学 + 控制总管理**（`chassis_motion`，保留为独立模块）
   - cmd(v,θ,w) → 麦轮解算 → 四轮目标速度 ω*
   - 保留 `move_scale/rotate_scale`（按底盘类型）设计，保留数据流 v/θ/w → ω*

2. **电机反馈链路**
   - ω* → 速度PID（**位置式**，积分累加）→ 电流指令 `I_raw`
   - 速度环外置（从 dji_motor 移出，原 `PID_MODE_DELTA` → `PID_MODE_POSITION`）
   - 读实测速度闭环；读回功率控制后的电流做反算
   - 运行在 htim5 定时器中断（注册先于 dji_motor，同一拍算完电流、dji_motor 接着发，延迟最小）

3. **功率控制**
   - 收应用层传来的**绝对功率上限**（W）→ `I_raw` → 预测功率 → 缩放比 k → `I = k·I_raw` → 电机
   - 二值化（buffer vs 阈值 → 上限）放**应用层**，[3] 只做纯限幅（见五）

## 三、数据流

```
cmd(v,θ,w) ── chassis.c（指令对接）
  ├─ [1] 运动学+控制总管理：cmd → 麦轮解算 → ω*（保留 scale 设计）
  ├─ [2] 电机反馈链路：ω* → 速度PID → I_raw（读实测速度闭环）
  └─ [3] 功率控制：I_raw → 预测功率 → 缩放比 k → I = k·I_raw
                         └── I 回灌 [2]：integral -= (1-k)·I_raw·coef
  → DJIMotor_Set_Current(4 轮)
```

## 四、积分反算抗饱和（反馈链路）

pid 库自带抗饱和只知道自身 output_min/max，**不感知功率控制对电流的二次限流**。所以：

1. pid 库加 `PID_Set_Integral(instance, value)`；`PID_Reset_Integral` 包装成 `Set_Integral(instance, 0)`（原调用点不变）。
2. 反算：`integral -= (1-k)·I_raw·coef`，k=缩放比，I_raw=原始电流指令，coef=反算增益（量纲，≈1/Ti，实现时调）。前提是速度环用**位置式**（integral 为累加器，反算才能扣它）。

### coef 为什么 ≈ 1/Ti（= ki/kp）

integral 的单位是「误差×时间」（deg/s·ms），被扔掉的 `(1-k)·I_raw` 单位是 A，二者不能直接相减，靠 coef 换算。coef 有两种选法：

- **精确清零** `coef = 1/ki`（本参数下 =2000）：令 `ki·Δintegral = (1-k)·I_raw`，一步减掉被限掉的电流贡献。太猛——积分被瞬间清空，可 error 还在，下一拍又从头攒，速度响应发肉。
- **跟踪（back-calculation）** `coef = 1/Ti = ki/kp`（≈0.07）：让反算按「积分自己增长的速度」衰减。`Ti = kp/ki` 是恒定 error 下 I 项追上 P 项所需时间（本参数 = 0.007/0.0005 = 14ms）；每拍（1ms）衰减 1/Ti 比例，匹配积分自然节奏，既不清空也不拖沓。

默认 `back_calc_coef = ki/kp = 0.0005/0.007 ≈ 0.07`，实现时按限流时的速度响应（发肉/过冲）微调，取值落在 `1/Ti`（顺滑）到 `1/ki`（硬）之间。

## 五、二值动态限功率

```
buffer_energy > 阈值(20J,可配)  →  放开，允许超功率（从缓冲扣）
buffer_energy ≤ 阈值            →  限死在 chassis_power_limit
```

阈值做成 config 参数，测试定。

**分层**：二值化决策在**应用层**（读裁判 `buffer_energy` / `chassis_power_limit` + 阈值 → 绝对功率上限 `limit`），[3] 只收 `limit`（W）做纯限幅，不碰裁判/阈值。「放开」用 `limit<=0` 表示（scale 直接 =1），限死时传绝对上限。当前二值化在 `cmd.c` 中注释掉，测试时固定上限 60W。

## 八、速度环力矩/电流前馈（规划中，暂不实现）

速度环是纯 PI 反馈：稳态电流靠积分一点点「扛」出来（摩擦 + 负载），有滞后。可给速度环加基于**目标速度**的前馈，稳态电流由前馈直接给出，反馈只修误差：

```
I_ff = sign(ω*) · (a·|ω*| + b)
```

- `a` = 粘滞摩擦折算电流（正比 |ω|）；`b` = 库仑摩擦折算电流（常量 `τ_C/Kt`）。
- 标定：闭环扫一组恒定速度，稳态记 `(ω, I_raw)`，对 `|I_raw| = a·|ω| + b` 线性回归得 a、b。
- 注入位置：在功率预测**之前**——`I_raw = PI输出 + I_ff`，功率预测/限流按总电流算（前馈也受功率上限约束）。
- 实现：两参数模型别硬塞 pid 库的单增益 FEEDFORWARD，直接在 `chassis_velocity` 显式加 `a·ω* + b·sign(ω*)` 更清楚。
- **不用平滑 sign 的 2b 跳变**：那是扭矩阶跃不是速度跳变（速度 = ∫加速度连续），车身惯量吸收；C620 内部只做电流环跟踪、不平滑电流，正好忠实执行前馈扭矩。
- **云台速度环同样适用**（规划，未实现）：云台惯量小、摩擦占比更高，前馈收益更明显，后续 gimbal 规划时复用此模型。

## 九、功率测试 LED 指示（cmd.c，测试用）

底盘功率测试时的 RGB 指示（`cmd.c` `Cmd_Task`，替换了原小电脑/自瞄指示）：

| 功率 P (W) | 颜色 | 含义 |
|----|------|------|
| P ≤ 60 | 绿 | 正常，未触上限 |
| 60 < P ≤ 检测值 | 蓝 | 触及/超过上限 |
| P > 检测值 | 红（锁存，永久） | 失控，超过检测值 |

- 上限固定 60W（`CHASSIS_POWER_LIMIT`），检测值 70W（`CHASSIS_POWER_DETECT`，可改 65）。
- 红为锁存：一旦超过检测值永久红（`power_over_detect` 静态标志），需复位清除。

## 十、备选限流分配（备注，暂不做）

当前 [3] 用**等比缩放**（四轮电流同乘 k）把预测功率压到上限——简单，但各轮「贡献功率」与「贡献运动」的比例不同，等比缩放不是最优分配。

另一套思路：**递归最小二乘（RLS）在线辨识系统参数**（Kt、摩擦等），超功率时**手动求解最优电流指令**（在满足底盘合力/合力矩约束下最小化功率、或按权重分配四轮电流），比等比缩放更有意思。先记一笔，暂不实现。
