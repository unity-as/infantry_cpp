# delta 反馈 → 统一前馈（自瞄 + 键鼠）

> 最后更新：2026-08-17
> 覆盖范围：自瞄（视觉 delta）与键鼠手动（鼠标 delta）共用的「位置环 P + 速度前馈」手法
> 关联：[aim.md](aim.md)（自瞄链路细节与符号约定）

## 一、核心洞察：两种模式反馈的都是 delta

小电脑（视觉）和鼠标，反馈的都是**差值/增量**，本质同源：

| 来源 | 反馈的是什么 | setpoint |
|------|------------|----------|
| 视觉（自瞄） | 「目标相对当前」的误差（符号约定见 aim.md） | 恒 0 |
| 鼠标（键鼠） | 「相对上次」的增量 | `setpoint += delta` |

差别只在 setpoint 语义（恒定 0 vs 累加），控制手法完全通用。

## 二、统一手法：位置环(P) 绝对纠偏 + 速度前馈消滞后

- **位置环纯 P（不加 I）**：做绝对纠偏 + 软件限位。目标在动，加 I 会 windup/过冲。
- **速度前馈**：把 delta 携带的速度信息直接注入速度环，消掉位置环的稳态滞后（`e_ss = ω_target / kp`）。

### 为什么「速度前馈 = 隐式插帧」

两次更新之间以恒定速度（= delta/T）运动，位置轨迹就是线性斜坡——这正是插帧。所以**只做速度前馈就够了，不用单独写插帧逻辑**。

## 三、键鼠前馈（可直接实现）

```c
float dt         = 实际帧间隔;                        // 图传有抖动，别写死 75Hz(≈13.3ms)
float vel_yaw    = -MOUSE_GIMBAL_YAW_SCALE   * delta_mouse_x / dt;
float vel_pitch  = -MOUSE_GIMBAL_PITCH_SCALE * delta_mouse_y / dt;
Gimbal_SetVelocityFF(gc, vel_yaw, vel_pitch);        // 符号与位置增量一致（都取负）
```

- 接口现成：`Gimbal_SetVelocityFF`（gimbal_core 已有 `vel_ff`，`vel_target + vel_ff` 喂速度环）。
- 位置环保留（kp 绝对纠偏 + 软件限位），鼠标速度 → `vel_ff`。
- 鼠标静止 `delta=0` → `vel_ff=0` → 云台自然停，无漂移。

### 三个注意

1. **T 用实际到达间隔**（DWT 时间戳）：图传帧有抖动，固定 T 会在抖时算出错误 velocity、尖峰复现。
2. **vel_ff 轻滤波**：鼠标有手抖，直接 delta/T 会抖，套一阶低通（α≈0.3）更稳。
3. **符号与位置增量一致**（yaw/pitch 都取负，见 `Cmd_Mouse`）。
